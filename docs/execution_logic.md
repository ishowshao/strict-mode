# StrictMode 执行逻辑说明

## 📋 概述

StrictMode 有两个主要执行路径：
1. **CLI命令**：用户手动触发的建仓/清仓操作
2. **每日任务**：自动运行的止损价更新和触发检查（尚未实现）

---

#### 历史数据获取时机详解

**关键代码位置**：`strictmode/cli.py:91-92`

```python
data_source = container.data_source()
df = data_source.get_adjusted_daily(symbol)
```

**获取时机**：
- ✅ **每次执行 `buy` 命令时实时获取**
- ✅ **在检查幂等性之后立即获取**
- ✅ **在计算止损价之前必须完成**

**数据来源**：
- Alpha Vantage API (`TIME_SERIES_DAILY_ADJUSTED`)
- 使用 `outputsize=full` 参数获取**完整历史数据**
- 不是增量获取，而是**每次都拉取全部历史数据**

**数据内容**：
```python
# 从 Alpha Vantage 获取的数据包括：
- date (索引)
- open, high, low, close (原始价格)
- adj_close (复权收盘价)
- volume (成交量)

# 程序内部计算：
- ratio = adj_close / close
- adj_open = open * ratio
- adj_high = high * ratio
- adj_low = low * ratio
```

**数据使用**：
```python
# 只使用最新的 N*2 条数据（默认44条，用于ATR窗口22）
df_for_calc = _latest_bars(df, config.atr_period * 2)  # 44条
stop_price = _compute_initial_stop(df_for_calc, config, previous_stop)
```

**为什么需要 N*2 条数据？**
- ATR计算需要至少 N 条数据（默认22条）
- 为了确保有足够的历史数据计算准确的ATR
- 使用 `min_periods=N` 确保前 N 条数据可以正确计算

### 2. CLI命令：`strictmode sell-all <SYMBOL>`

执行步骤较简单：

```
1. 检查持仓是否存在
2. 删除数据库中的止损记录（⚠️ 当前未取消IBKR实际订单）
3. 连接IBKR并下达平仓单
4. 删除数据库中的持仓记录
5. 发送通知
```

**注意**：当前实现中，`sell-all` 命令**没有获取历史数据**，因为清仓不需要计算止损。

## ⚠️ 当前实现的问题

1. **没有数据缓存**：
   - 每次 `buy` 都拉取完整历史数据，API调用成本高
   - 缺少 `price_cache` 表实现

2. **每日任务未实现**：
   - 缺少自动获取最新EOD数据的逻辑
   - 缺少数据新鲜度检查

3. **数据获取效率**：
   - 可以考虑增量获取（只获取新数据）
   - 或者使用缓存机制减少API调用

---

## 💡 优化建议

1. **实现 price_cache 表**：
   - 缓存已获取的EOD数据
   - 每日任务优先从缓存读取

2. **增量数据获取**：
   - 记录上次获取的日期
   - 只获取新的数据点

3. **数据新鲜度检查**：
   - 验证最新数据日期是否匹配目标交易日
   - 如果滞后，拒绝操作并告警
